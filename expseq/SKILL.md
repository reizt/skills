# Sequential Explainer

読み手が前提知識ゼロでも迷わず理解できるように、番号付きの順序立てた説明を作る。

## 手順

1. 読み手が知っている/知らないことを推定する。初出の用語・略語・社内固有の概念・登場人物を洗い出す。
2. 説明対象を並べる順序を決める。「原因→結果」「時系列」「依存関係(AがないとBが成立しない)」のどれに当たるか考える。
3. 各ステップを1つの事実・アクションだけに絞り、番号付きリストに落とす。
4. 専門用語が出たら初出時に一言(括弧書きでOK)で補足する。前提を端折らない。読み手基準で「これは知らないかもしれない」と思ったら一段掘り下げる。
5. 最後に「結局どうなったか/結局何をすればいいか」を一言で締める。

## 出力

ステップは JSON に書き、ローカルサーバーで読み手に1ステップずつ確認してもらう。チャットにはステップを書き出さず、URL だけを渡す。
Issue やドキュメントに貼る文面を頼まれたときは、サーバーを使わず番号付きリストを本文に書く。

```json
{"title": "…", "steps": [{"text": "○○とは△△のことである"}, {"text": "そのため□□という問題が起きた"}], "summary": "結局…"}
```

- `text` はプレーンテキスト。バッククォートで囲んだ部分だけコードとして表示される。
- `summary` は手順5の締めの一言。
- コードや文書の特定箇所を見せたいステップには `"ref": {"path": "/絶対パス", "start": 10, "end": 24}` を付ける。画面に「該当箇所を表示」ボタンが出て、横のペインに範囲をハイライトして表示する。`end` を省くと1行、`start` も省くとファイル全体。存在しないパスは起動時にエラーになる。Markdown はプレビューで開き、範囲と重なるブロック（リストは項目）に印が付く。正確な行はソース表示に切り替えて見られる。

1. scratchpad（なければ作業ディレクトリ）に `steps.json` を書く。
2. Bash の `run_in_background` で起動し、出力された URL を渡してターンを終える。ポーリングしない。`scripts/` はこのスキルのディレクトリからの相対パス。

```sh
node scripts/serve.mjs steps.json
```

3. 読み手が送信するとサーバーが出力して終了し、セッションが再開する。

各ステップには「理解した／異論がある／わからない」の選択と自由入力が付く。出力は `番号 選択：自由入力` の形で届く。

- 「理解した」に書かれた理解は、ズレている箇所だけ指摘する。合っていれば一言で済ませる。
- 「異論がある」には、根拠を示して答える。説明が誤っていたら認めて訂正する。
- 「わからない」と質問には、そのステップを掘り下げて答える。

出力が `--- 回答 ---` のとき：上の方針でチャットに答える。

出力が `--- 説明依頼 ---` のとき：
1. そのステップの `detail` に、`text` より詳細度を上げた説明を書く。選択と自由入力が届いていれば、上の方針での答えを説明に織り込む。既に `detail` があれば、さらに噛み砕いて置き換える。
2. ステップの追加・削除・並べ替えはしない。画面の入力は番号に紐づいて保存されているため。
3. 出力の再開オプションを付けて再起動し、ターンを終える。開いているページは再読み込みなしで説明欄だけ更新される。

```sh
node scripts/serve.mjs steps.json --port PORT --token TOKEN
```

読み手がチャットで直接返事をした場合は、待機中のサーバーを止める。

## 注意点

- ステップ数は事柄の複雑さに応じて増減してよい。3つや5つに無理に揃えない。
- 1ステップに複数の情報を詰め込まない。詰め込みたくなったらステップを分割する。
- 事実の整理が目的なので、評価・感想・意見を勝手に足さない。元の発言や資料にないものは書かない。
