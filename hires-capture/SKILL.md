# 高解像度の画面キャプチャ

ブラウザペイン（`mcp__Claude_Browser__computer` の screenshot）や Claude in Chrome のスクリーンショットは、トークン節約のため 800x500 前後に縮小されて返る。ペイン側で解像度を上げる設定は無い。人に見せるキャプチャでは小さい文字やタグが潰れるので、別のヘッドレスブラウザで `deviceScaleFactor: 2` を指定して撮る。

ペインのスクリーンショットは、Claude 自身が画面を確かめる用途にはそのまま使ってよい。このスキルは「人が読む画像」を作るときに使う。

## 方針

- `playwright-core` だけを npm から入れ、ブラウザ本体はダウンロードせず、インストール済みの Google Chrome を `channel: "chrome"` で動かす。数 MB で済み、Chromium の数百 MB のダウンロードが要らない。
- `playwright-core` はリポジトリの外のキャッシュ（既定は `~/.cache/hires-capture`）に入れる。作業中のリポジトリの `package.json` や lockfile を変えないため。初回だけユーザーにダウンロードの許可を取る。
- シナリオファイルと撮った画像は scratchpad に置く。リポジトリに残すものではない。
- シナリオごとに新しいブラウザコンテキストを作る。前の操作の状態（開いたドロワー、URL の query、ローカルストレージ）が次の画像に混ざらない。その代わりログインは毎回通るので、ログイン手順をシナリオファイルに書く。

## サブエージェントに任せる

撮影はサブエージェントに任せるのを基本にする。画面を探ってシナリオを書く手間、失敗の調査、画像の確認はトークンを食うが、撮る対象が決まっていればメインの判断は要らない。

渡すもの：

- 撮る画面と状態（どの URL で、何を選び、何が写っていればよいか）
- 比べる版（コミットやブランチ）と、サーバーの立て方（例：`vite --mode mock --port <port> --strictPort`）
- 画像の大きさの指定があればそれと、出力先のディレクトリ
- このスキルの手順に従うこと。立てたサーバーは止めて終えること

返してもらうもの：

- 画像のパスと、それぞれに何が写っているかを 1 行ずつ
- 失敗して直したことがあれば、その原因

メインは返ってきた画像を手順 4 の縮小版で確かめるだけにする。撮る対象がまだ決まっていない、画面の操作手順をユーザーと相談しながら決める、といった場合はメインで進める。

## 手順

### 1. 準備

```bash
~/.claude/skills/hires-capture/scripts/setup.sh
```

`playwright-core` が無ければキャッシュに入れ、キャッシュのパスを出力する。2 回目以降は何もしない。

### 2. シナリオファイルを書く

`assets/scenarios.example.cjs` を scratchpad に複製し、作業に合わせて書き換える。

- `baseUrl`：撮る画面のオリジン。ローカルの https proxy は自己署名証明書でもそのまま開ける（`ignoreHTTPSErrors: true` を設定済み）。
- `login`：ログイン画面に飛ばされたときの操作。デバッグログインのボタンを押す、など。認証情報の入力が要る画面は、テスト用の値を扱える条件（ローカルの開発ホスト）を満たすときだけ書く。
- `scenarios`：画像 1 枚ごとの操作。`open(path)` で開き、要素が出るまで `waitFor` で待つ。切り出したい要素があれば、その locator を返す。

シナリオを書くときに気を付けること：

- 先にブラウザペインで実際に操作し、`read_page` や `find` でボタン名やテキストを確かめてから書く。推測で書いた locator は外れやすい。
- 要素の操作は Playwright の locator（`getByRole`、`getByText`）で書く。`click()` は要素が表示され、押せる状態になるまで自動で待ち、失敗したときは「見つからない」「押せない」などの理由をエラーに出す。`page.evaluate` で DOM を探して押す自作の関数は、押せない要素を見落として「見つからない」としか言わないので使わない。
- 待つときは条件で待つ。`locator.waitFor()`、`page.waitForLoadState("networkidle")`、`page.waitForResponse()` を使い、固定の `sleep` は入れない。一覧の再取得で要素が描き直されても、locator の `click()` は描き直された要素を探し直す。固定の `sleep` は撮影 1 枚あたりの時間を延ばすうえ、遅い環境では足りずに失敗する。
- 撮る対象はデータの条件で選ぶ。mock のデータは読み込むたびにランダムに作られることがあり、「一覧の先頭」のように位置で選ぶと、条件を満たさない対象（電話番号がない、案件がない、など）に当たって失敗する。API の応答から条件を満たす対象を探し、その名前や ID で locator を作る。
- トースト（保存失敗の通知など）が写り込むときは、`waitFor({ state: "detached" })` で消えるのを待つ。
- AS-IS と TO-BE を並べるときは、同じシナリオを両方の環境で撮り、`window.scrollBy` などでスクロール位置を揃える。見出しの位置を基準にすると、ヘッダーの高さが違っても揃う。

### 3. 撮る

```bash
node ~/.claude/skills/hires-capture/scripts/capture.cjs <scenarios.cjs> <出力ディレクトリ> [シナリオ名...]
```

- シナリオ名を省くと全シナリオを撮る。
- `<名前>.png` に画面全体を、locator を返したシナリオは `<名前>-crop.png` に周辺 16px 付きで切り出しを保存する。
- 失敗したシナリオは `_failed-<名前>.png` にそのときの画面を残し、次のシナリオへ進む。1 つでも失敗すると終了コードが 1 になる。
- 失敗したら、再実行する前に `_failed-<名前>.png` を手順 4 の縮小版で見て、原因を特定してシナリオを直す。再実行で通っても、同じ原因でまた落ちる。
- 画面サイズと倍率は環境変数 `WIDTH`、`HEIGHT`、`SCALE` か、シナリオファイルの `viewport`、`deviceScaleFactor` で変えられる。縦に長い画面を丸ごと撮るときは、シナリオファイルに `fullPage: true` を書く。

### 4. 確かめる

撮った画像を開き、狙った状態が写っているかを確かめてから人に渡す。ドロワーが開き切っていない、ローディング表示が残っている、データが空、といった失敗はスクリプトの終了コードでは分からない。

確かめるときは、横 1000px に縮めた複製を Read する。2560px の元画像をそのまま読むと 1 枚 3〜5k トークンかかるが、縮小版なら 4 分の 1 ほどで済み、写っている状態の判断には十分読める。人に渡すのは元画像のほう。

```bash
mkdir -p <出力ディレクトリ>/_check
for f in <出力ディレクトリ>/*.png; do sips -Z 1000 "$f" --out <出力ディレクトリ>/_check/ >/dev/null; done
sips -g pixelWidth -g pixelHeight <出力ディレクトリ>/*.png
```

元画像が 2560x1600 になっていることも確かめる。

### 5. 渡す

- PR やコメントに貼るときは `gh-image-upload` スキルで URL を発行する。
- PR 本文の画像を差し替えるときは、更新前の本文をファイルに退避し、差し替え後の本文の長さと画像の数が想定どおりかを確かめてから `gh pr edit` する。元にする本文ファイルが空のまま更新すると、本文が消える。

## つまずきやすい点

| 症状 | 原因と対処 |
|---|---|
| `Cannot find module .../playwright-core` | `setup.sh` を実行していない。または `HIRES_CAPTURE_HOME` を変えたのに setup と capture で値が違う |
| `Chromium distribution 'chrome' is not found` | Google Chrome が入っていない。ユーザーに確認し、入れられない場合だけ `npx playwright-core install chromium` で Chromium を入れて `channel` を外す |
| 毎回ログイン画面が写る | `login` の locator が合っていない。ブラウザペインでログイン画面を開き、ボタン名を確かめる |
| 画像が 1280x800 のまま | `deviceScaleFactor` が 1 になっている。`SCALE` の指定を確かめる |
| 切り出しがずれる | locator が想定より外側か内側の要素を指している。`xpath=ancestor::section[1]` のように、切り出したい枠の要素まで上る |
| 同じシナリオが通ったり落ちたりする | mock のランダムなデータで、条件を満たさない対象を選んでいることが多い。`_failed` の画像でボタンが押せない状態になっていないか見て、対象をデータの条件で選ぶ |
| 1 枚の撮影に 10 秒以上かかる | 固定の `sleep` が積み重なっている。条件で待つ形に置き換える |
